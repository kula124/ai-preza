# Case Study #2: Internal Tool

## Traditional Approach (What We Avoided)

- Define the problem
- Scope to MVP
- Have devs work overtime / off-project
- **Maybe have something after 6 months**

## We Decided to Try Something Different

### The Team:

- 3 senior devs
- 1 lead designer
- COO

### The Process:

1. **Meeting**: Talk about the problem
2. **Recording**: 1 hour and 37 minutes, transcribed
3. **AI Processing**: Transcription fed to AI
   - Turned into feature set and MVP definition
   - **15 minutes of adjustments**
   - Turned into set of tasks using AI
4. **Developer Agent**: Fed to agent, worked non-stop for 36 hours

## The Result

An MVP solution that **works**:

- ✅ All features implemented
- ❌ Very shitty code
- ❌ Lots of UI bugs

Now we can **test and "feel"** the solution before deciding next steps.

## The Point

**Outside of the meeting we spent 0 dev hours to make this tool.**

The tool works (has all the features), it just has bad QA.
